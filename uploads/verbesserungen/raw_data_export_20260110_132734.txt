## 1. Redesigned Process Flow
- All warranty requests are registered digitally via a customer self-service portal, collecting all required information upfront.
- Automated triage (workflow engine) classifies requests into "simple" (likely straightforward) and "complex" (ambiguous or high-value) based on predefined rules and data analytics.
- For "simple" cases:
  - The system assigns the case directly to "check ticket" (Ellen or Pete).
  - After ticket check, the case is routed to Sara for decision.
  - If approved, compensation is paid by Ellen or Mike; if rejected, rejection is processed by Ellen.
- For "complex" cases:
  - After registration, the system assigns the case to Sean for "examine thoroughly" (skipping "examine casually").
  - After thorough examination, the case is routed to Sara for decision.
  - If approved, compensation is paid by Mike; if rejected, rejection is processed by Pete.
- Eliminate the "examine casually" activity for all cases classified as "complex" and remove unnecessary rework loops by preventing cases from returning to previous steps unless new information is provided by the customer.
- The "reinitiate request" activity is only triggered if the customer provides substantial new evidence; otherwise, cases are closed after decision.
- All case progress is tracked and visible in the digital workflow system, with automated notifications to customers.
- Each case is assigned a case manager (Ellen for simple, Sean for complex), responsible for end-to-end coordination and minimizing handovers.

## 2. Assigned resources
1. **Ellen**: Case manager for simple cases; handles "check ticket," "pay compensation," and "reject request" for simple cases.
2. **Pete**: Supports "check ticket" for simple cases; processes "reject request" for complex cases.
3. **Mike**: Handles "pay compensation" for complex cases.
4. **Sara**: Sole decision-maker for all cases.
5. **Sean**: Case manager for complex cases; conducts all "examine thoroughly" activities.
6. **Sue**: No direct assignment in the optimized flow (can be backup for "examine thoroughly" if compliance permits in the future).

## 3. Major changes
- Automated digital triage replaces manual routing and reduces unnecessary "examine casually" steps for complex cases.
- Elimination of unnecessary rework and loops by restricting "reinitiate request" to cases with new evidence only.
- Case managers assigned to each case type to reduce handovers and coordinate activities end-to-end.
- "Examine casually" activity is only performed for simple cases, never for complex ones.
- All activities are tracked and coordinated in a workflow management system, reducing manual coordination and administrative overhead.

## 4. Used process redesign patterns
1. Apply triage
2. Eliminate activities
3. Appoint case managers
4. Apply integral technology (digital workflow automation)

## 1. Redesigned Process Flow

- **Customer submits warranty request via a standardized digital portal** with mandatory fields and guided input to ensure all required information and documents are collected upfront.
- **Automated triage system** immediately classifies the request based on complexity and completeness:
  - *Simple/standard claims* are routed for "casual examination".
  - *Complex/unclear claims* are routed for "thorough examination" (by Sean).
- **Automated ticket review** is performed instantly upon submission to check for completeness and eligibility, using pre-configured business rules.
- **Case manager (Pete)** is automatically assigned to each case upon registration, responsible for tracking progress, coordinating handoffs, and ensuring timely resolution.
- **Examination step**:
  - If "casual examination" is required, assigned to Mike or Ellen based on experience and workload.
  - If "thorough examination" is required, assigned to Sean.
- **Decision step**:
  - Only Sara is permitted to decide, but cases are queued digitally for her, prioritized by oldest first and flagged for rework if returned.
- **If additional information is needed**, the case manager triggers a single, consolidated request to the customer via the portal, pausing the process until all data is received.
- **If rework is triggered** (e.g., after "decide" or "check ticket"), the case is routed directly back to the relevant examination step with all previous findings attached, avoiding redundant ticket reviews.
- **Upon decision**:
  - If compensation is approved, "pay compensation" is triggered automatically and assigned to Ellen or Mike.
  - If rejected, the case is closed and the customer is notified via the portal.
- **All process steps and customer communications are logged automatically** for transparency and ISO 10002 traceability.

## 2. Assigned resources

1. **Pete**: Case manager for all warranty cases; oversees progress, coordinates handoffs, communicates with customers.
2. **Mike/Ellen**: Perform "casual examination" and "pay compensation" steps; assigned based on workload and experience.
3. **Sean**: Conducts all "thorough examination" steps.
4. **Sara**: Solely responsible for all "decide" steps.
5. **Digital Portal/System**: Handles registration, automated triage, ticket review, workflow routing, and customer communication.

## 3. Major changes

- Introduction of a standardized digital portal for upfront data collection and customer interaction.
- Automated triage and ticket review to eliminate manual delays and misrouted cases.
- Assignment of a dedicated case manager (Pete) to each case for end-to-end coordination.
- Digital workflow routing to ensure only necessary steps are executed, and rework is minimized by routing cases with full context.
- Elimination of redundant "check ticket" and "examine casually" loops by consolidating information requests and attaching all prior findings to rework cases.
- Digital queue management for decision steps, ensuring Sara handles only eligible cases in priority order.
- Full process transparency and traceability via system logging.

## 4. Used process redesign patterns
